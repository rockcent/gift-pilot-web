# Web MVP · 礼有方网页端（C 端用户界面 + 管理后台）· 产品规格

**对应 PRD**：礼有方 AI 原生小程序 V0.6（高保真页面图）
**对应宪法**：`.specify/constitution.md` v0.2 §3.1
**最后更新**：2026-07-06

---

## Feature Summary

把小程序端的 10 步 C 端用户体验**完整搬运**到网页端（H5/PC 自适应），并在 `/admin/*` 子路由下新增一个**最小可用的平台管理后台**，让运营 / 商家 / 机构视角能直接查看并操作关键数据。

## User Flows

### Flow A：C 端用户界面（与小程序 1:1）

A1. **首页 / 表达需求** — AI 对话输入区 + 需求概览卡 + 今日推荐机会横滑；
A2. **AI 选品** — Tab「最匹配 / 更体面点 / 佣金更高」+ 礼物卡列表；
A3. **内容生成** — Tab「文案生成 / 话术 / 短组画 / 图文策略」+ 3 段风格化文案；
A4. **封面设计** — 风格选择「简约高级 / 温柔治愈 / 清新自然 / 复古轻奢」+ 封面预览；
A5. **发布确认** — 内容预览 + 渠道多选 + 发布时间建议 + 内容质量评分；
A6. **发布成功** — 大对勾 + 「查看 / 分享 / 继续生成」CTA；
A7. **订单与佣金** — 3 张数据卡 + 筛选 + 订单列表；
A8. **经营复盘** — 总发布 / 总订单 / 佣金 + 4 张二级数据 + 亮点 + 下周建议；
A9. **AI 下一步计划** — 周计划 4 行 + 关系差异化提醒 + 一键生成内容；
A10. **我的 AI 记忆** — 6 条记忆可编辑 + 清空记忆。

### Flow B：管理后台（/admin/*）

B1. **登录** `/admin/login` — 单一密码登录（MVP 阶段 mock），session 存 localStorage；
B2. **仪表盘** `/admin` — 4 张关键指标卡（DAU / 发布数 / 订单数 / GMV）+ 4 张二级指标 + 7 日趋势图（mock SVG）；
B3. **商品管理** `/admin/gifts` — 礼物列表（CRUD）+ 筛选 + 批量上下架；
B4. **订单管理** `/admin/orders` — 订单查询（按状态 / 时间 / 用户）+ 详情抽屉 + 状态调整 mock；
B5. **用户管理** `/admin/users` — 用户列表 + 详情（含 AI 记忆只读视图）；
B6. **内容审核** `/admin/content` — 小礼生成内容列表（mock）+ 详情预览 + 通过/打回（mock）；
B7. **AI 记忆审核** `/admin/memory` — 异常记忆审计列表（标记需复审）+ **不可编辑**（宪法 §6.8 红线）；
B8. **财务概览** `/admin/finance` — 佣金趋势图 + 提现申请列表（mock）+ 结算状态。

## Acceptance Criteria

### AC-Web-1 全局体验
- [ ] 全局背景 `--brand-bg` (#FAF9F6)，主色 `--brand-green` (#23B26D)。
- [ ] Logo「礼有方 GiftPilot」+ 主口号「送礼有方，推荐有数」在 footer。
- [ ] C 端有顶部导航（首页 / 推荐 / 内容 / 发布 / 复盘 / 我的）+ 底部信息栏。
- [ ] 管理后台有独立 layout（左侧栏 + 顶部 bar + 内容区）。
- [ ] 6 大 AI 体验标签在 C 端首页底部展示。

### AC-Web-2 C 端 10 页面
- [ ] 与小程序 1:1 视觉与交互（参考 .specify/features/mvp-v0/spec.md AC-2~AC-11）。
- [ ] 响应式：H5 (< 768px) 单列布局；PC (>= 768px) 居中卡片 + 侧栏（推荐场景）。

### AC-Web-3 管理后台登录
- [ ] `/admin/login` 输入密码（占位 `admin123`，mock）；
- [ ] 登录成功跳 `/admin`；失败提示；
- [ ] 未登录访问 `/admin/*` 重定向到 `/admin/login`；
- [ ] session 在 localStorage，logout 清除。

### AC-Web-4 仪表盘
- [ ] 4 张关键指标卡：DAU 1,234 / 发布数 856 / 订单数 312 / GMV ¥98,420；
- [ ] 4 张二级指标：复盘触发率 78% / 内容生成 1,902 / 封面设计 1,536 / AI 记忆使用率 64%；
- [ ] 7 日趋势 SVG 图：发布 / 订单 / 佣金 3 条曲线；
- [ ] Top 5 礼物 + Top 5 推荐对象横向柱状图。

### AC-Web-5 商品管理
- [ ] 礼物列表分页（10 / 页）；
- [ ] CRUD 操作：新增 / 编辑 / 上下架；
- [ ] 字段：礼物图 / 名称 / 品牌 / 价格 / 分类 / 关系标签 / 匹配度 / 上下架状态；
- [ ] 批量上下架 + 筛选（按分类 / 状态）。

### AC-Web-6 订单管理
- [ ] 订单列表分页（10 / 页）；
- [ ] 字段：订单号 / 用户 / 礼物 / 金额 / 佣金 / 状态 / 创建时间；
- [ ] 详情抽屉：完整订单字段 + 发布归因链路（publish_id → recommendation_id）；
- [ ] 状态调整：mock（CREATED → PAID → CLOSED），写操作日志。

### AC-Web-7 用户管理
- [ ] 用户列表分页（10 / 页）；
- [ ] 字段：昵称 / openid / 注册时间 / 订单数 / 总佣金 / AI 记忆开关；
- [ ] 详情抽屉：基本信息 + AI 记忆**只读**视图（不可编辑，宪法 §6.8 红线）。

### AC-Web-8 内容审核
- [ ] 小礼生成内容列表（按用户 / 时间筛选）；
- [ ] 详情预览：原文案 + 封面 + 评分 + 关联礼物；
- [ ] 通过 / 打回按钮（mock，不影响发布状态）。

### AC-Web-9 AI 记忆审核
- [ ] 异常记忆列表：异常预算 (>¥1000) / 异常类目（医疗 / 投资品）；
- [ ] 每条可标记「需复审」（mock，写操作日志）；
- [ ] **不提供**编辑入口（页面必须有明显提示「用户自有，admin 不可修改」）。

### AC-Web-10 财务概览
- [ ] 7 日佣金趋势 SVG 图；
- [ ] 提现申请列表（用户 / 金额 / 状态 / 时间）+ 通过/驳回 mock；
- [ ] 结算状态汇总（待结算 / 已结算 / 已提现）。

### AC-Web-11 合规与质量
- [ ] 所有金额以「分」存储；
- [ ] admin 路由有 session 鉴权中间件；
- [ ] admin 所有写操作记录操作日志（`admin-audit.json` mock）；
- [ ] 没有真实 admin 密码 / 私钥入仓；
- [ ] 没有真实 AppID / 私钥入仓。

## Out of Scope（MVP v0.6 网页端阶段）

- 多租户 / 子账号 / RBAC；
- 真实支付 / 真实 LLM / 真实商品 API（同宪法 §8.2 豁免）；
- 真实 OAuth / 短信 / 邮箱登录；
- 礼有方 Pro / 礼有方云 / 开放平台；
- 国际化（先 zh-CN）；
- 移动端 App（仅 H5 / PC Web）。

## 与小程序端的关系

- 视觉规范完全一致（宪法 §2）；
- 类型 / mock 数据 / 服务接口形态 1:1 同步（手动，阶段二起抽到 shared 包）；
- 用户从 C 端任一入口（小程序 / 网页）产生的数据，在管理后台统一可见（mock 阶段同源 JSON，阶段二起共享云数据库）。
